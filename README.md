# 🍸 Телеграм-бот поиска рецепта коктейля
## 🎯 Замысел
Изначально витала идея реализовать возможность поиска по, главным образом, алкогольным коктейлям, исходя из наличия имеющихся у пользователя ингредиентов. А чтобы он мог сохранять свои находки, можно было реализовать функцию генерации QR-кода. Однако в ходе предпроектного анализа выяснилось, что подобная возможность не будет востребованной по ряду причин. 

В связи с этим было решено вместо генерации кодов реализовать озвучку рецептов. 

Практическая (_для пользователей_) задумка вызвана фактом того, что имеющиеся возможности синтеза речи не очень хорошо (скорее всего, это реализуемо) воспроизводят интонацию и эмоции, то при прослушивании результата пользователь улыбнётся, покажет/перешлёт товарищу рецепт, и, тем самым, запомнит, что можно сделать из различных ингредиентов. 

Непосредственно мне интересно было попробовать поработать с `RAG`-приложением. По этой причине рецепты, которые по ингредиентам желает получить пользователь, ориентируются на книгу _Тима Федерле_ "**Мастер шейков и «Маргариты»**". Каждый представленный в книге рецепт литературоцентричен, поэтому одноимённый коктейль здесь назван иначе, а на его рецептуру должен опираться бот при генерации результата поиска. В случае, когда поиск не даёт результата, AI-агент генерит нечто самостоятельное, но ориентируясь на контекст книги, размещённый в векторном хранилище. Также важно отметить реализацию приложения с упором на использованием не-платных моделей. Это, с одной стороны, способствует сохранению работоспособности решения при независящих от нас факторов (невозможность оплаты, блокировки), с другой, накладывает потребность в добротном локальном железе, доступном в режиме, близком к 24/7.

### Отель `У погибшего пессимиста`
К сожалению, в рамках разработки существует ряд нерешённых (надеюсь, пока) моментов, которые не позволяют использовать RAG всю мощь данного решения. Они представлены ниже. Поскольку я не специалист в `ML` и даже не программист, то разбираюсь по мере сил и возможностей. Самая главная проблема на текущий момент - неудовлетворительный поиск по ингредиентам в векторном хранилище `FAISS`. Притом, что поиск по писателям или контексту гораздо лучше. 

Все выявленные проблемы обозначены внизу. Время функционирования бота ограничено преимущественно вечерним временем, поскольку упирается в имеющиеся локальные ресурсы.

## 🚀 Начало работы

### 📋 Требования к системе
- Доступ к глобальной сети Интернет
- 🐍 Python 3.12+
- 🐳 Docker
- 🤖 Локальная модель Ollama
- 💾 ~14 Гб свободного места
- 📦 Зависимости из requirements.txt

### 🔑 Предварительная настройка
1. Создайте в телеграмм через `BotFather` бот и получите ключ API доступа к нему
2. Создайте файл `.env` с ключами `HUGGINGFACEHUB_API_TOKEN` и `TELEGRAM_BOT_TOKEN`:
   ```
    - HUGGINGFACEHUB_API_TOKEN = ключ
    - TELEGRAM_BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN_HERE
    # опционально (в перспективе)
    - SBER_API_KEY = ключ_авторизации
    - OPENAI_API_KEY = ключ
   ```
3. Ежели решили использовать запуск моделей локальных, чтобы денежку не тратить зазря, тогда необходимо предварительно запустить модель. Например, 
   ```bash
   ollama run mistral:instruct
   ``` 

### 📥 Установка и локальный запуск
1. Склонируйте репозиторий:
   ```bash
   git clone git@github.com:trofimovelijah/cocktail_qr.git
   cd cocktail_qr
   ```
2. Создайте и активируйте виртуальное окружение:   
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # Linux/MacOS
   ```
3. Установите зависимости:   
   ```bash
   pip install -r requirements.txt   
   ```
4. Запустите `Ollama` в новом терминале:  
   ```bash
   ollama run mistral:instruct   
   ```
5. Запустите бота:   
   ```bash
   python /models/telegram_bot.py
   ```

Преимущества этого подхода:
- 🚀 Более быстрая работа языковой модели
- 💾 Меньше потребление памяти
- 🔄 Возможность использовать Ollama для других проектов
- 🛠️ Проще обновлять модель

## ✨ Особенности реализации
1. 🏗️ **Архитектура бота**:
   - Синхронная работа через ConversationHandler
   - Модульная структура с разделением ответственности
